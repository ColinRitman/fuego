KEY ARCHITECTURAL DECISIONS (FINAL)
================================================================================

✅ ELDERFIERS VS. COLDAO: Completely Independent
   - Elderfiers control HEAT/COLD burn/deposit fees
   - COLDAO controls interest rates
   - No overlap, separate treasuries
   - 100% of fees to elderfiers, 0% to miners

✅ SUBMISSION FREQUENCY: Hybrid Event-Driven + Periodic Aging
   - Submit when root changes (immediate)
   - Resubmit when aged > 600 blocks (~5 minutes)
   - Daily cost: ~$5-15 USD
   - User experience: Claim window guaranteed within 5 minutes

✅ PRIVACY MODEL FOR ELDERFIERS: Hashed Alias (MVP)
   - Public alias: FIRENODE (8 chars, human-readable)
   - Hashed address: 0x1f3e5d7c (keccak256, semi-public)
   - Real address: Private (owner-only access)
   - Privacy rating: 3/5 (good enough for MVP)
   - Future upgrade: ZK-STARKs via circom (Phase 2+)

✅ UNLOCK WINDOW: User-Initiated with 8-Day Countdown
   - Phase 1 (Staking): Indefinite, no countdown
   - Phase 2 (Request): User initiates unstaking
   - Phase 3 (Countdown): 8-day clock starts
   - Privacy benefit: No automatic timestamp reveals

✅ ALIASES ON FUEGO CHAIN: Native Support
   - 0xEA transaction tag for alias registration
   - Stored directly on Fuego blockchain
   - RPC endpoints for lookups
   - 21 hours to implement (2-3 days)
   - Effort: Minimal, can do during Dynamigo

✅ ZK-STARK FOR ALIASES: Defer to Phase 2
   - Use circom + snarkjs (NOT xfg-stark)
   - xfg-stark produces 1000x larger proofs (not suitable)
   - Phase 2 implementation: 2-3 weeks post-MVP
   - Optional layer, not required for launch
